## What to build

使用者講完話、修訂落檔之後，**當場就知道這批修訂會不會炸**，不必等一次昂貴的上游重跑才發現。

「由上游套用」這個設計的代價是效果不即時：講完話 json 不會變。乾跑是對這個代價的補償。

### 做什麼

落檔後，把**完整的累積修訂集**（不只這次新增的那幾筆）套到當前的 `workflow.json` 或 `workitems.json` 上，跑契約驗證與工項顆粒度底線，收集 warnings 與孤兒清單——**不寫回任何 json**。

回報內容接在「這次寫進去的每一筆全文」後面：

- 契約驗證過或不過，不過時的完整錯誤訊息
- 顆粒度底線有沒有跌破
- 哪些修訂現在是孤兒（錨指向的 Page 或工項在當前 json 裡不存在）

### 不帶修改需求的體檢模式

```
f2w-revise <workflow|workitems>
```

不帶第二個參數直接觸發時，跳過「產出 Revision」與「落檔」兩步，**只做乾跑與回報**。用途是體檢目前累積的修訂是否還健康——上游動過之後，可以隨時問一句「我的校正現在還有幾筆錨得住」。

### 一致性靠共用實作，不靠測試比對

乾跑呼叫的必須是 T2／T3 建的**同一支 `applyRevisions`**，`f2w-describe`、`f2w-breakdown`、乾跑三處共用。兩份實作會漂，乾跑報「沒問題」而上游實際套出來炸掉，比沒有乾跑更糟。

這條約束要寫進 ADR-0012（T2 已建立該 ADR，本票補上這段）：**未來如果有人在上游加了額外的後處理，這個保證就破了。**

## Acceptance criteria

- [ ] 落檔後自動跑一次乾跑，回報接在每一筆修訂全文之後
- [ ] 乾跑套的是完整累積修訂集，不只本次新增的幾筆
- [ ] 乾跑**不寫回任何 json**（測試直接驗檔案內容未變）
- [ ] 修訂會導致契約驗證失敗時，乾跑報出完整錯誤訊息，但落檔仍然成立（修訂已經寫進去了，使用者自己決定要不要改）
- [ ] 修訂會跌破工項顆粒度底線時，乾跑報出來
- [ ] 乾跑列出當前的孤兒修訂清單，指名錨在哪裡
- [ ] `f2w-revise <target>` 不帶修改需求時只做乾跑與回報，不寫任何東西
- [ ] 乾跑與 `f2w-describe`／`f2w-breakdown` 共用同一支 `applyRevisions`，沒有第二份套用實作
- [ ] ADR-0012 補上「乾跑與上游實際套用必須共用同一份實作」這條約束，以及它在什麼情況下會被破壞
- [ ] `f2w-revise` 的 SKILL.md 寫明乾跑的存在、它不寫回、以及體檢模式的用法
