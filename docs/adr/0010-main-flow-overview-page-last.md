# 總覽頁回到最後一頁：全部主線由上到下排一頁

Main flow diagram 的最後一個 draw.io 分頁固定是**總覽**（`Diagram_Overview`，分頁名 `總覽`＝`OVERVIEW_PAGE_NAME`）：把每條主線那一列**照 `flows` 順序由上到下**排在同一頁，內容與該主線自己那頁**逐字相同**（同樣的標題、細橫線、步驟框、tooltip、邊 label、色系），只換 y 座標。本 ADR 只取代 **ADR-0008 的「要不要總覽頁」一節**（原決定「不要總覽頁」），並讓 ADR-0009 開頭列在「全部續用」裡的「不要總覽頁」那一項失效；兩份 ADR 其餘各節（主線邊界＝頂層 Page 分類、分頁名照抄、推論落在可手改的 `mainflow.json`、只留主幹、一步可收多頁、邊 label AI 寫＋真實邊硬驗、圖上不標「推論·待確認」與 ⚠、四道硬驗、確定性範圍）**全部續用**。

起因是 ADR-0009 的 9 分頁實跑給業主看：分類方式對了，但要看懂「整個平台有多少事、哪條線長哪條線短」得逐個翻頁籤，簡報與列印時沒有一張全景可用。draw.io 的頁籤只給得出名字，給不出比例感。

## Considered Options

**要不要總覽頁（重新決定）**

- **維持 ADR-0008 的「不要總覽頁」**：頁籤本身就是目錄。但目錄不是全景——業主要的是一眼看完，而不是知道有哪幾頁。
- **總覽畫成「主線之間的關係圖」**：ADR-0008 否決過，這裡**繼續否決**。主線之間本來就沒有先後關係（頂層分類彼此並列），畫出來只會退化成 9 個色塊並排。
- **最後一頁原樣堆疊每條主線那一列（採用）**：不是新的一張圖，是**同一批圖元換 y 座標重排**。沒有新語意、沒有新推論、沒有新契約欄位，所以也沒有新的出錯面。

**要不要嵌匯出的 PNG**

- **否決**：得先匯出 PNG 再 base64 塞進 `.drawio`，檔案暴增，且 `mainflow.drawio` 不再是由 `mainflow.json` 確定性產出的明文檔（PNG 會隨 draw.io 版本與 GPU 變動）。ADR-0006 的「明文不壓縮」與重跑逐字元可比因此都會破功。原樣重排圖元同樣達到「把前面各頁由上到下放在一起」的效果，代價為零。

**放最後而不是放第 1 頁**

- 業主看圖的主路徑仍是「側欄看到哪個模組、就翻到那一頁」，第 1 頁保持第一條主線（ADR-0008 那條理由沒變）。總覽是拿去簡報與列印的全景，放最後不擋路；`--all-pages` 匯的 PDF 也剛好收在全景那一頁。

**主線只有一條時**

- **仍然照出**：總覽頁與第 1 頁內容相同。分頁位置固定（最後一頁一定是總覽）好過視情況消失——下游（driver 斷言、業主翻頁習慣）不必分兩種情況。

## 實作落點

- 色系由 `DiagramPage.colorIndex` 移到 **`DiagramNode.colorIndex`**：總覽頁一頁就有全部主線的色，色不能再掛在分頁上。`FLOW_PALETTE` 與取色規則（依主線順序、超過循環）不動。
- layout 抽成 `buildFlowRow(flow, flowIndex, idPrefix, yOffset)`：主線頁傳 `("", 0)`、總覽頁第 n 列傳 `("Overview_", n * ROW_SPACING)`，`ROW_SPACING = STEP_Y + STEP_HEIGHT + 80`（＝310px）。**同一段 layout 程式產兩種頁**，所以總覽頁不可能與主線頁長得不一樣。
- 圖元 id 加 `Overview_` 前綴，維持「節點與邊 id 跨分頁都不重複」那條既有測試。

## Consequences

- **0729 實跑結果**：10 分頁（9 條主線 ＋ 總覽）。總覽頁 26 步、17 條邊、44 個 vertex（26 步＋9 標題＋9 橫線），內容範圍 2280×2670px；`--all-pages` PDF 匯出 715214 bytes。
- **總覽頁的寬度由最長那條主線決定**（0729 是 `算力排程與工作負載` 7 步 ＝ 2340px），短的主線右邊留白。這是刻意的：每列左對齊才比得出長短。
- **四道硬驗與契約一行未動**：總覽頁不為任何 Page 表態，涵蓋完整性與真實邊驗證的輸入完全相同。
- **分頁數變成 `flows.length + 1`**，兩支 driver 的斷言跟著改；log 改成數 `kind === "step"`——原本的 `page.nodes.length - 2` 只對「一頁一列」成立，在總覽頁會少算 8 條主線的標題與橫線。
- **匯出仍要真的看一眼，而且要會分辨假影**：本次 PNG 匯出時 draw.io 吐 `GPU state invalid after WaitForGetOffsetInRange`，縮圖上看起來像有兩行標題疊在一起；回查 XML 座標（44 個 vertex 無同座標）並把該列單獨以 2× 匯出，才確認是檢視端縮放的假影、檔案本身正確。看圖存疑時回頭驗座標，不要憑縮圖改版面。
